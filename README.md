# CSV 清理

按块排序 + 多路归并的 CSV 清理工具：页面选择排序字段、空值顺序与重复保留规则，
任务运行时显示已读行数、临时分片与合并进度，完成后可预览、搜索、下载。

纯 Python 3.11 标准库实现（`http.server` + SQLite + 手写 HTML/CSS/JS），无第三方依赖、无构建步骤。

```bash
python3 run.py                          # 打开 http://127.0.0.1:8000/
python3 -m unittest discover -s tests   # 42 个测试
python3 tools/make_samples.py --edge --out samples/edge.csv
python3 tools/bench.py --rows 300000    # 本机实测，非吞吐承诺
```

## 1. 处理模型：输入从不整体进内存

```
输入 CSV ──► 顺序扫描，按块排序 ──► scan 分片(JSONL) ──► 去重/归并 ──► cleaned.csv
             （每块≈chunk 字节）      （已排序，可校验）   （fan-in 上限的多层归并）
```

**扫描（scan）**：从输入文件顺序 `readline()`，按配置的行数或字节数（`chunk_rows` /
`chunk_bytes`，默认 200000 行 / 4 MiB，任一先到即切块）把一批记录读进内存，
排序后写成一个 `scan-000NN.jsonl` 分片。块大小由**实际写出的字节**计量：累计到
`chunk_bytes` 就切块，所以一个分片最多超出你设定值一条记录的大小，不会多出一整块。
只有当前这一块在内存里。

**去重（dedupe）**：若保留规则是 `latest`/`first`，先对 scan 分片按业务键做一次多路归并，
同一键的相邻记录只留一条，输出按显示顺序排序的 `value` 分片；`keep` 则跳过此步。

**归并（merge）**：对若干有序分片做 k 路堆归并。分片数超过 `fan_in`（默认 16）时先合并成
`merge-L1-*` 中间层，逐层收敛，最后一遍写入 `cleaned.csv`。任何时刻打开的读取器不超过
`fan_in` 个，内存不随文件行数增长。

页面的分片表与柱状图展示的就是实际生成的 `scan` / `value` / `merge L1…` 分片及其字节数
（`app/static/app.js` 的 `renderShardChart`）。

### 排序与类型

排序比较使用真实类型，不按字符串：

| 模式 | 解析 | 说明 |
|---|---|---|
| `number` | `decimal.Decimal` | 去掉 `,` `$ ¥ € £`，支持 `(1,234.50)` 负数写法；`9.10 < 10.00` |
| `date` | `datetime` | ISO、`YYYY/MM/DD`、`DD/MM/YYYY`、`YYYYMMDD` 等；非法日期是坏行 |
| `text` | 原字符串 | 字典序 |
| `auto` | 按值打类型标签 | 数字 < 日期 < 文本；同类型内按真实值比较 |

空值（空串、`-`、`n/a`、`null` 等）单独成桶，按 `nulls=first|last` 放到最前或最后，
永远不会和非空值做类型比较。降序用预计算的整数/取负 token 实现（`_payload_key`），
比较仍发生在 C 层。

### 稳定性

每条记录带原始**物理行号**与**字节偏移**。所有比较器最后都以
`(字节偏移, 原始行号)` 收尾，所以：

- 值相等时保持输入顺序；
- 重复键时间相同（或没有时间列）时，由原始行号决定保留哪条；
- 同样输入 + 同样规则 + 同样块配置，重跑输出**逐字节相同**（自测中对比 SHA256）。

## 2. 记录切分与坏行

`RecordSplitter` 是按物理行推进的引号状态机，不把整份文件交给 `csv.reader`：

- **引号内换行**：一条逻辑记录可以跨多个物理行，切分器在引号关闭前不切记录；
- **转义引号** `""` 正确跳过；引号内 `,` 不是分隔符；
- **坏行**：列数不符、类型解析失败（如金额非数字、日期非法）、解码失败、引号始终未闭合
  （超过 64 行判为坏行，后续行重新扫描，不会吞掉整个文件）。

坏行**不进入结果**，但保留**原始位置**，写入 `bad_rows.csv`（下载 `kind=bad`）：

| start_line | end_line | byte_offset | reason | raw |
|---|---|---|---|---|
| 6 | 6 | 219 | 更新字段 updated_at：非法日期 '2024-02-30 10:00:00' | … |
| 9 | 9 | 398 | 排序字段 amount：invalid number 'not-a-number' | … |
| 11 | 11 | 515 | 列数不符：期望 6，实际 8 | … |

每个 scan 分片都有配套的 `bad-000NN.jsonl` 边车文件，与分片一起校验、一起恢复。

`samples/edge.csv` 手工覆盖了：引号内换行、`""` 转义、空金额、非法日期、
重复业务键新旧两条、非法金额、列数不足/过多 —— 10 条记录 / 12 物理行，
预期 7 好 / 3 坏 / 去掉 1 条重复 / 输出 6 行。

## 3. 中断恢复：只复用「已完成且已核对」的分片

每个分片写入记录：`rows`、`bytes`、`sha256`、`offset_end`（输入字节位置）、
`lines_end`（物理行号）、`verified=1`。

恢复时（`Runner._recover_scan`）：

1. 只取**从 1 开始连续**的 scan 分片（中间缺一个就停）；
2. 逐个重新计算文件大小与 SHA256，与记录不符即停 —— 篡改/截断的分片不会被信任；
3. 每个 scan 分片还必须有对应的、同样校验通过的 bad 边车；
4. `offset_end` 必须 ≤ 当前输入大小；
5. 校验失败的尾部与之后的产物全部删除，从断点继续扫描。

`value`/`merge` 分片只在 `dedupe_done=1` 时复用，归并中间层每次都重建。
进程重启后，原本 `running`/`pausing` 的任务标为 `interrupted`，点「恢复」即可续跑。
自测（30 万行输入）：在已校验 2 个、6 个、15 个 scan 分片处分别强制中断再续跑，
三种情况的结果 SHA256 都与不中断的一次完全一致（`1db14ce9…`）。

### 任务身份：换了输入或规则绝不混用旧结果

任务键 = `sha256(输入内容) + 输入大小 + 编码/分隔符/表头 + 列名 + 全部规则 + 块配置 +
引擎版本 + 语义版本`。同一键复用同一任务；任何一项变化都生成新任务，不会接管旧分片。
启动前还会再核对一次输入文件的 SHA256 与大小，不一致则任务标为
`input_changed` 并拒绝续跑（HTTP 409）。

## 4. 页面控制

- **暂停 / 恢复**：引擎在每行读取与每个分片边界调用 `Control.checkpoint()`；暂停时阻塞，
  进度不再增长。
- **取消**：抛出 `TaskCancelled`，只清理**本任务**名下的临时分片与工作目录
  （`tasks/{id}/work`），共享的上传文件保留。
- 删除任务会先停止再清理；无法及时停止时返回 409。

## 5. 实际使用的分片与资源（本机观测）

以下数字是**本机、本样本、本次运行**的观测，不是吞吐承诺；磁盘、CPU 与数据形状不同，
结果就不同。可随时用 `tools/bench.py` 在本机重测。

机器：Linux 6.6 / WSL2，12 核，Python 3.11.2，工作目录在 C: 盘（`/workspace`）。

**`--rows 300000`，默认块 200000 行 / 4 MiB，fan-in 16**

| 项 | 值 |
|---|---|
| 输入 | 300000 条记录 / 337567 物理行 / 17.8 MiB |
| 墙钟 / 引擎计时 | 9.3 s / 9.2 s（重复运行在 9–13 s 间波动） |
| 峰值 RSS（含本进程其它开销） | 42.2 MiB |
| 结果 | 299402 好、598 坏、去掉 199402 重复 → 100000 行 / 5.9 MiB |
| 分片 | 13 scan + 5 value = 18 个文件，共 65.4 MiB（约为输入的 3.7 倍） |
| 最大块分片 | 25044 行 / 4.0 MiB（在 4 MiB 处切块） |

**同一输入，块 50000 行 / 1 MiB，fan-in 4**（用于展示多层归并）

| 项 | 值 |
|---|---|
| 墙钟 | 12.3 s |
| 峰值 RSS | 30.5 MiB |
| 分片 | 50 scan + 17 value + 5 `merge L1` + 2 `merge L2` = 74 个文件，98.1 MiB（约 5.5 倍输入） |
| 最大块分片 | 6329 行 / 1.0 MiB |

读法：块越小 → 分片越多、临时字节越多（每层归并都要重写一遍数据）、墙钟略慢，
但峰值内存更低。临时字节约为输入的数倍是块排序 + 归并的固有代价，页面与 `bench.py`
都直接显示这个倍数，而不是隐含它。

## 6. 目录

```
run.py                 入口（默认 127.0.0.1:8000，数据目录 ./data）
app/typed.py           记录切分（引号状态机）、类型解析、日期、规则
app/storage.py         SQLite 任务/分片元数据（WAL）
app/engine.py          扫描→分片→去重→归并，校验与恢复，进度与取消
app/service.py         任务生命周期、上传、预览/搜索/下载（可直接单测，不依赖 HTTP）
app/server.py          HTTP 路由与静态文件
app/static/            index.html / app.css / app.js（无构建步骤）
tools/make_samples.py  大样本生成器 + 手工边界样本（--edge）
tools/bench.py         跑一次并打印分片布局与资源占用（本机观测）
tests/                 42 个 unittest
samples/edge.csv       手工边界样本（620 字节）
```

数据目录（默认 `./data/`，可用 `--data-dir` 或 `CSV_CLEAN_DATA` 指定）：
`uploads/` 按内容哈希存放上传（同内容只存一份）、`tasks/{id}/` 放结果与临时文件、
`tasks.sqlite3` 存元数据。`data/` 与 `samples/generated/` 不纳入版本控制。
